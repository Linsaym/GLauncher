# Архитектура GLauncher

| Область           | Точка входа                                        | Ответственность                                                                                   |
| ----------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Electron main     | [index.ts](../apps/client/src/main/index.ts)       | Окно Windows, настройки, установка, проверка серверов, синхронизация и управление процессом Java. |
| Electron preload  | [preload.cts](../apps/client/src/main/preload.cts) | Контракт [LauncherApi](../apps/client/src/main/contract.ts) через `contextBridge`.                |
| Electron renderer | [index.tsx](../apps/client/src/renderer/index.tsx) | Локальный React-интерфейс, настройки и отображение прогресса.                                     |
| Сервер обновлений | [index.ts](../apps/update-server/src/index.ts)     | Самостоятельный процесс Node.js. Публикует моды из заданной папки.                                |

## Клиент

Main проверяет отправителя IPC и валидирует данные настроек. Renderer загружается из локального Vite-бандла, работает в sandbox и обращается к main через методы preload. Один экземпляр лаунчера держит блокировку на время своей работы. Main допускает одну операцию запуска и не меняет настройки во время неё.

Изолированный корень — `%AppData%\GLauncher`. Java устанавливается в `runtime`, метаданные и установщик кэшируются, а каталоги игры, моды и `servers.dat` находятся в `game`. Клиент загружает архив Temurin по API Adoptium, метаданные закреплённой версии Minecraft, артефакты из них и установщик NeoForge из официального Maven. Встроенная контрольная сумма установщика проверяется до чтения профилей. Официальный NeoForge InstallerTools локально применяет патч к скачанному Minecraft. В стартовой команде объединяются аргументы версий и подставляется локальный профиль с детерминированным UUID. При смене адреса Minecraft обновляется запись лаунчера в NBT-списке серверов.

Перед установкой main проверяет доступность манифеста. После установки main получает актуальный список и сверяет локальные JAR по имени, размеру и SHA-256. Новая сборка готовится во временной папке, после загрузок манифест запрашивается повторно. Если он не изменился, каталоги переключаются переименованием с резервной копией для восстановления после ошибки или прерывания. При ошибке игра не запускается. Отдельно главный экран проверяет `/health` и выполняет запрос статуса по протоколу Minecraft Java.

В набор клиентских модов входят Horizon Iris Fork с CurseForge и Sodium с Modrinth с закреплёнными контрольными суммами. Узнаваемые JAR этих модов из манифеста имеют приоритет. Синхронизация добавляет обе группы в один набор и проверяет актуальность исходного манифеста перед заменой каталога. Лаунчер кладёт ресурспак в `game/resourcepacks` и загружает шейдерпак в `game/shaderpacks`. Русский язык и выбор паков записываются один раз в `options.txt` и `config/iris.properties`, включая уже существующие установки GLauncher. Следующие запуски сохраняют настройки игрока.

## HTTP-контракт

Портативный сервер Windows поставляется отдельно. Скрипт `start-server.bat` запускает собранный сервер через Node.js из архива, используя каталог BAT как рабочую папку.

| Метод и путь                  | Успешный ответ                                                                                                                                            |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /health`, `HEAD /health` | `204`, папка модов доступна.                                                                                                                              |
| `GET /manifest`               | `200` и JSON с полями `version: 1` и `mods`. Каждый элемент содержит `name` (имя JAR), `size` (байты) и `sha256` (64 строчных шестнадцатеричных символа). |
| `GET /mods/<name>`            | `200` и содержимое файла. Имя — один URL-кодированный сегмент.                                                                                            |

Сервер читает обычные JAR из корня папки, сортирует записи по имени и отдаёт ответы с `Cache-Control: no-store`. Коллизии имён без учёта регистра и имена, недопустимые в Windows, приводят к ошибке манифеста. Неизвестный маршрут или отсутствующий файл возвращает `404`, неподдерживаемый метод — `405`, сбой чтения каталога или манифеста — `503`. Манифест удостоверяет целостность файла относительно опубликованной сборки. Подлинность HTTP-ответа зависит от доверенной сети.
